# Threat model

All domain data is synthetic. **Implemented** controls are scoped to current offline code and tests; **Planned** controls are not validated features. This is a design review aid, not certification. See [architecture](ARCHITECTURE.md) and [evidence convention](README.md#evidence-convention).

## Assets, actors and boundaries

**Implemented assets:** local configuration, synthetic credentials/fixtures, caller-scoped documents/claims, embeddings, deterministic outcomes, extractive answers, traces, synthetic budgets and build integrity. **Planned assets:** real-provider/evaluation evidence.

**Implemented actors:** trusted operator/database, contributors, CI dependencies, synthetic customer/broker/underwriter/admin, adversarial fixture author and offline fake provider. **Planned:** external generation provider and production identity. The signed stub authenticates only a local fixture subject.

**Implemented trust boundaries:** environment to settings, host to local database, repository to CI, signed subject to authoritative DB identity, documents to untrusted evidence context, fake output to verified extraction and reported synthetic usage to cost records. Real provider mapping remains Planned.

## Assumptions and limits

The machine/operator and repository reviewers are trusted; synthetic passwords are not deployment secrets. Fixture access and extractive output validation are implemented; production identity, rate limiting, real generation and calibrated evaluation are not. Model artifacts are revision-pinned with local hash verification, but initial HTTPS downloads trust the publisher and cache metadata is not signed. [Adapter smoke tests](../tests/test_embedding_adapter.py) cover shape, offsets and query prefixes, not complete supply-chain defence. The [backlog](BACKLOG.md) records unresolved work.
